Baseball Win Probability

Recreating the idea behind a live win probability bar.

An early machine learning experiment inspired by the win-probability graphics shown during baseball broadcasts. I used historical Retrosheet game data to explore whether a neural network could estimate how likely a team was to win as a game progressed.

Can game context, the current score, and team performance be combined into a useful in-game win estimate?

01 · The Idea

A baseball question turned into an ML experiment.

I have always been interested in the win probability meters that appear during sports broadcasts. This project started as a simple question: could I build my own version for baseball using historical game data?

The goal was a general method rather than a Dodgers-only predictor. I used a smaller two-team setup, including the Los Angeles Dodgers as my main proof of concept, to keep the first implementation manageable and easy to test.

1. Collect Build a historical dataset from completed baseball games.
2. Learn Train a neural network to classify the eventual winner.
3. Test Live States Feed partial game snapshots into the model and read the output as a win estimate.

02 · The Data

Turning box-score information into model features.

Historical game records were manually collected from Retrosheet. I chose a manual collection workflow rather than building a scraper, then reorganized each game into a consistent team-versus-opponent representation for training.

Game Context

Game number, day of week, day/night, game duration, home/away, and extra innings.

Current Score

Team score and opponent score, treated separately because score matters differently as a game gets later.

Offensive Performance

At-bats, hits, doubles, triples, home runs, RBI, walks, strikeouts, stolen bases, and runners left on base.

Pitching & Defense

Pitchers used, earned runs, errors, double plays, and additional team-level game statistics.

Source: Retrosheet game logs. The raw project dataset contained dozens of fields; the final experimental network used a reduced representation after preprocessing.

03 · Model & Approach

Make score and game time matter, not just the box score.

The most important design idea was that the same statistics should not mean exactly the same thing at every moment of a game. A two-run lead in the second inning is very different from a two-run lead in the eighth.

Game Features Team and opponent statistics
→
Score + Duration Processed as explicit context
→
Feature Interactions Combine context with learned features
→
Win / Loss Output Softmax converts outputs to probabilities

The final PyTorch experiment separately processed score and game duration, combined those signals with learned game features, and then passed the interaction representation through dense layers for a two-class output.

05 · Result

A useful proof of concept, with room to make the probability model more rigorous.

91.9% Held-out winner classification accuracy

The final saved experiment correctly classified the eventual winner in approximately 91.9% of the held-out test games.

Important: this is classification accuracy, not a measure of probability calibration. A stronger modern version of the project would explicitly evaluate calibration, temporal generalization, and uncertainty before treating the output as a production-quality live win probability.

06 · Reflection

A personal passion project and an early step into machine learning.

This project combined two things I cared about: baseball and predictive modeling. It gave me hands-on experience turning messy real-world data into a complete ML workflow — collecting and cleaning data, designing features, training a neural network, and testing it on situations that looked different from the completed games used for training.

Looking back, I would put more emphasis on probability calibration, chronological train/test splits, feature ablations, and a cleaner live-data pipeline. That is also what makes the project useful to revisit: it shows an early experiment that I can now evaluate with a much stronger ML perspective.
